考点 5：大模型 Agent
权重 16%。课程：课时 6-9。
真实痛点
Agent 是把执行权交给 AI：你说目标，它自己规划步骤、读写文件、调用工具、操作浏览器，把任务做完。企业最怕的不是 Agent 不够聪明，而是两件事。一件是把不该交的任务交出去了，一句话能答的问题也大动干戈；另一件是交出去之后没人盯着，自动发错邮件、删错文件，损失收不回来。备考这个考点，就是练会划这两条线：什么任务该交给 Agent，交出去之后哪些环节必须人盯着。
场景精讲
场景一：什么活都想交给 Agent，可行吗？
一家电商公司的运营主管听完 Agent 的课很兴奋，列了个“全面 Agent 化”清单：回答客户常见问题、生成商品文案、每月从五个系统导数据汇总成经营分析报告、帮设计师想海报创意。技术同事看了说：这四件事里只有一件适合做成 Agent。
怎么分析
：用三问过筛：是不是多步骤？需不需要读写文件或调用工具？是不是要自动执行？三条都沾才值得上 Agent。拿这四件事逐条过。回答常见问题是一问一答，大模型直接对话就够；生成商品文案是单步任务，提示词就能解决；想海报创意是开放式创作，没有固定流程。只有“每月导数据汇总报告”三问全中：要导出、清洗、汇总、成文好几个步骤，要连五个系统的接口，还要每月固定自动跑。部署和维护 Agent 是有成本的，一句话能答的问题包成 Agent 是浪费投入。还有一点容易想反：给 Agent 接工具不是越多越好。每个工具的描述和参数都占模型的“工作记忆”（上下文），装一堆用不上的工具，长任务跑到后面 Agent 反而“失忆”。只接当前任务需要的工具，这是真实项目里排查过无数次的经验。
对应考法
：给几个任务问哪些适合 Agent，干扰项把简单对话任务也列进去；或问“接入大量工具后长对话质量下降为什么”，干扰项是“工具越多能力越强”。往上下文占用上想就对了。
课程出处
：课时 6《安装桌面 Agent，开始用它干活》、课时 7《让 Agent 接入知识库和工具》。
场景二：同样的活每月都干，为什么每月都重新教一遍？
一家连锁餐饮品牌的财务，每月底让 Agent 把上百家门店交上来的发票文件整理归档：按门店分文件夹、按日期命名、汇总成一张台账。每次都要把要求重新交代一遍——命名规则、台账字段、异常发票怎么处理，漏交代一条，Agent 就按它自己的理解来，月底对账就会暴露问题。
怎么分析
：这就是 Skill 要解决的问题：把跑顺的工作方法保存成可复用的规则，下次同类任务 Agent 照着做，不用每次重新交代。但固化有条件，重复性高、标准固定，两条同时满足才值得做成 Skill。每月发票归档完美符合；一次性的活动策划、标准还在变的任务，固化了反而绑住手脚。Skill 用不顺时排查分两个方向，别搞反。该触发没触发，先查描述信息，看“整理发票”“归档”“做台账”这些用户会说的说法写进去没有；触发了但生成缺项，查正文规则，看命名规则、异常处理流程写全没有。还有一个团队落地时必须想清楚的问题：Skill 放在个人目录下，只有你自己能用；放在项目目录下，团队成员才能共享同一套标准。想让全部门统一动作，就放项目里。
对应考法
：问“哪种任务适合固化为 Skill”，找“重复加稳定”双特征，干扰项是“越复杂越该固化”。问“Skill 没触发或生成缺项先查什么”，记住不触发查描述，缺项查正文。再就是个人目录和项目目录的区别。
课程出处
：课时 8《用 Skill 固化你的工作方法》。
场景三：Agent 说“自检通过了”，能直接发出去吗？
一家 SaaS 公司的客户成功团队让 Agent 起草续约方案：读客户的使用数据，生成续约报告和报价单，自检一遍后发给客户。流程跑了一周很顺，直到有个客户发现报价单上的折扣算错了一档——Agent 自检时没看出来，邮件已经发出去了。
怎么分析
：两个认知要纠正。第一，自检闭环不是免检金牌。自检是 Agent 检查自己的输出，同一个模型的判断盲区，自检时依然存在。它能拦住低级错误，比如数字抄错、事项遗漏；但拦不住判断性错误，比如折扣逻辑本身就理解偏了。第二，有些动作天然不该自动执行。删除、发送、付款、对外发布、关键决策，这些操作执行快、批量大，发出去的邮件收不回来，必须停下等人确认。续约报价既是对外发送又涉及金额，双料高危，正确的流程是 Agent 生成、人审核、人发送。验收 Agent 的活也有一条原则：看它真实运行的结果，不看它自己的汇报。让它做个网页就真的打开浏览器看，让它写脚本就真的跑一遍，只看汇报文字等于让它自己给自己验收。
对应考法
：“Agent 生成财务报告后正确做法是什么？”干扰项是“自检过了就可以用”“直接发送”。“自检闭环能完全消除错误吗？”干扰项把“减少”偷换成“消除”。高危操作清单一沾就必须人确认，关键任务的兜底永远是人。
课程出处
：课时 9《给 Agent 加一道自检闭环》。
能力自查
学完课时 6-9，合上课程，逐条检查自己：
给一个任务清单，能用三问过筛（多步骤、要工具、自动执行）挑出适合 Agent 的任务
能说清为什么“工具装得越多 Agent 越万能”是误区（工具定义挤占上下文）
能判断一个任务适不适合固化成 Skill（重复性高 + 标准固定）
Skill 出问题时能分方向排查：不触发查描述，生成缺项查正文
能说清 Skill 放个人目录和项目目录的区别，以及团队统一标准该放哪
能背出高危操作清单：删除、发送、付款、对外发布、关键决策——必须人确认
能说清自检闭环的价值和局限：拦低级错误，拦不住判断性错误
能说清验收 Agent 成果要看真实运行结果，而不是看它自己的汇报
有答不上来的，就按下面的课程位置补。

场景练习
列出你这周做过的三件重复性工作，用三问过筛：哪件适合交给 Agent？其中哪一步可以固化成 Skill？如果交给 Agent 自动执行，哪个环节必须停下来等人确认？
闪卡
检查一遍自己对知识点的掌握。
易错点
“Agent 万能论”。
 简单问答、单步生成、一次性任务，大模型直接对话就够了。“所有任务都该交给 Agent”的选项一定是错的。
“自检过就不用审”。
 自检是同一个模型检查自己，判断盲区还在。对外发送、涉及金额的内容，自检通过也必须人审。
“MCP 工具越多越好”。
 每个工具都占上下文，装一堆用不上的，Agent 反而在长任务里遗忘任务主线。
“Skill 没触发就怀疑模型”。
 不触发先查描述（触发词覆盖），生成缺项才查正文。排查方向搞反是常见失分点。
